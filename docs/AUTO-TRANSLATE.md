# แปลอัตโนมัติ TH → EN / JA (สเปกงาน)

> สถานะ: **สเปก ยังไม่เริ่มทำ** (เขียน 23 ต.ค. 2569) · งานนี้คือ BACKLOG.md ข้อ 7 · prompt เริ่มแชทอยู่ใน PROMPTS.md (G)
> ก่อนเริ่มทำต้องได้คำตอบ "ต้องถาม Jimmi" ในข้อ 3.3 อย่างน้อยข้อ 1 (ผู้ให้บริการ) — ข้ออื่นใช้ค่าเริ่มต้นไปก่อนได้

## 1. ปัญหาและเป้าหมาย

ลูกค้า (ทีมการตลาด HRI DeOne) ไม่มีเวลาดูแลเนื้อหา 3 ภาษา แต่เว็บต้องมี EN/JA ครบ

เป้าหมาย:
- ทีมการตลาด **เขียนและแก้แค่ภาษาไทย** หน้า EN/JA เกิดและอัปเดตเอง
- คนตรวจภาษา (native) **แก้หน้า EN/JA ใน editor ปกติได้** และสิ่งที่เขาแก้ **ไม่ถูกทับ** ตอนภาษาไทยเปลี่ยน
- เห็นสถานะชัดว่าหน้าไหนยังเป็น AI ล้วน หน้าไหนคนตรวจแล้ว หน้าไหนตกยุคจากต้นฉบับ
- ไม่มีค่า license รายปี จ่ายแค่ค่า API ตามใช้ (บัญชีของลูกค้า) และคุมงบได้

## 2. Flow ผู้ใช้

1. **ทีมการตลาด (TH)** เขียน/แก้หน้าไทย → กด Publish/Update ตามปกติ · กล่อง "การแปล" ข้างหน้าแก้ไข: ติ๊ก EN / JA (คอร์สและหน้าติ๊กไว้ให้แล้ว, บทความติ๊กเอง)
2. **ระบบ** (เบื้องหลัง ภายในไม่กี่นาที): สร้างหรืออัปเดตหน้า EN/JA ที่ผูกกันด้วย Polylang · แปลทีละ block, ชื่อเรื่อง, excerpt, ช่องข้อมูลคอร์สที่ต้องแปล · ใช้อภิธานศัพท์ · เผยแพร่ตามนโยบายของภาษานั้น (ข้อ 4.6)
3. **คนตรวจภาษา** ได้อีเมลสรุปงาน (วันละครั้ง) → เปิดหน้า "งานแปล" ในหลังบ้าน → แก้ในหน้า EN/JA ตรงๆ → กด "ตรวจแล้ว"
4. **ภาษาไทยแก้ทีหลัง** → ระบบแปลใหม่เฉพาะ block ที่ภาษาไทยเปลี่ยน · block ที่คนแก้ไว้และต้นฉบับไม่เปลี่ยน = ไม่แตะ · block ที่คนแก้ไว้แต่ต้นฉบับเปลี่ยน = ไม่ทับ ขึ้นสถานะ ⚠️ ให้คนตรวจตัดสิน (แสดงข้อความไทยเดิม/ใหม่ + คำแปลเครื่องใหม่ให้เลือก)

สถานะต่อหน้าแปล (แสดงเป็น badge ในรายการโพสต์ + กล่อง "การแปล" + หน้า "งานแปล"):

| สถานะ | ความหมาย |
|---|---|
| 🤖 `machine` | แปลด้วย AI ยังไม่มีคนตรวจ |
| ✅ `reviewed` | คนตรวจกด "ตรวจแล้ว" และไม่มี block ค้าง |
| ⚠️ `outdated` | ต้นฉบับเปลี่ยนใน block ที่คนเคยแก้ ต้องตัดสิน |
| ⏳ `queued` / ❌ `error` | รอคิว / แปลไม่สำเร็จ (มีข้อความ error + ปุ่มลองใหม่) |

## 3. ข้อตัดสินใจ

### 3.1 ตัดสินแล้ว
- ทำเองใน `hri-core` (ทางเลือก A) ต่อยอด Polylang ฟรี — ไม่ใช้ Polylang Pro / WPML / Weglot / TranslatePress
- ภาษาต้นทาง = TH เท่านั้น (ไม่แปล EN→JA หรือย้อนกลับ)
- API key อยู่ใน `wp-config.php` เท่านั้น ห้ามอยู่ใน repo/DB · บัญชี API เป็นของลูกค้า

### 3.2 ค่าเริ่มต้น (ตั้งได้ใน Settings → การแปล ไม่ต้องแก้โค้ด)
| เรื่อง | ค่าเริ่มต้น |
|---|---|
| นโยบายเผยแพร่ EN | เผยแพร่ทันที |
| นโยบายเผยแพร่ JA | เผยแพร่ทันที + `noindex` จนกว่าจะ `reviewed` |
| แปลอัตโนมัติ | `course`, `page`, `trainer` ติ๊กไว้ · `post` ไม่ติ๊ก (ติ๊กรายเรื่อง) |
| อีเมลคนตรวจ | ว่าง (ไม่ส่ง) |
| งบต่อเดือน | ว่าง = ไม่จำกัด (แสดงยอดใช้อย่างเดียว) |

### 3.3 ต้องถาม Jimmi
1. ผู้ให้บริการ: Claude / OpenAI / DeepL (ผมเอน LLM เพราะรับ glossary + คำสั่งเรื่องน้ำเสียงได้ และภาษาญี่ปุ่นเชิงธุรกิจดีกว่า) → ทำ adapter ให้เปลี่ยนได้ แต่ต้องรู้ตัวแรกที่ใช้จริง
2. งบรายเดือนสูงสุด และใครเป็นเจ้าของบัญชี API
3. อีเมลคนตรวจ EN / JA (ลูกค้ามีคนญี่ปุ่นไหม — บริษัทแม่ HR Institute?)
4. JA ใช้ "เผยแพร่ + noindex" หรือ "ร่าง รอคนตรวจ"
5. บทความเก่า ~150 เรื่อง (หลังนำเข้าในงาน B): แปลทั้งหมด / เฉพาะเรื่องที่เลือก / ไม่แปล

### 3.4 ต้องถาม Ruk-com (เพิ่มใน BACKLOG.md ข้อ 7 รายการที่ 9)
- outbound HTTPS ไปโฮสต์ของ API ได้ไหม (เช่น `api.anthropic.com`, `api.openai.com`, `api.deepl.com`) และ timeout ของ PHP
- WP-Cron ทำงานได้ไหม / มี cron จริงของโฮสต์ให้ตั้ง `wp-cron.php` ทุก 5 นาทีได้ไหม
- Rcache: purge หน้าเฉพาะ URL จากโค้ดได้ไหม (hook/function ของ Rcache) — หน้า EN/JA ที่ระบบอัปเดตต้องไม่ค้าง cache

## 4. สถาปัตยกรรม (hri-core)

โมดูลใหม่ `wp-content/plugins/hri-core/inc/translate/` โหลดจาก `hri-core.php` หลัง `polylang` · ไม่มี build step (meta box คลาสสิก + JS ธรรมดาถ้าจำเป็น)

| ไฟล์ | หน้าที่ |
|---|---|
| `translate.php` | hooks: `save_post` ของต้นฉบับไทย → เข้าคิว · ตอนคนบันทึกหน้าแปล → ตรวจ block ที่คนแก้ |
| `segments.php` | แตก post content เป็น segment ตาม block และประกอบกลับ |
| `providers.php` | interface + adapter (Claude / OpenAI / DeepL / `fake`) |
| `queue.php` | คิวด้วย WP-Cron single event + lock + retry |
| `glossary.php` | อภิธานศัพท์ + คำสั่งน้ำเสียง |
| `admin.php` | Settings → การแปล, หน้า "งานแปล", กล่อง "การแปล", คอลัมน์สถานะ, อีเมลสรุป |

### 4.1 การตั้งค่าใน wp-config (ไม่มี = โมดูลปิดตัวเอง UI แสดง "ยังไม่ได้ตั้งค่า")
```php
define( 'HRI_TRANSLATE_PROVIDER', 'anthropic' ); // anthropic | openai | deepl | fake
define( 'HRI_TRANSLATE_API_KEY', '...' );
define( 'HRI_TRANSLATE_MODEL', '...' );          // ไม่บังคับ มีค่าเริ่มต้นต่อ provider
```
`fake` = pseudo-translation ไม่ยิงเน็ต (เช่น ใส่ `[EN] ` นำหน้าและคงแท็ก) ใช้ทดสอบใน local/Playground · cloud workspace มักยิง API ภายนอกไม่ได้

### 4.2 Segment (หัวใจของการไม่ทับงานคน)
- `parse_blocks()` ไล่ทุกชั้น (รวม innerBlocks) · segment = เนื้อ HTML ของ block ที่มีข้อความ: paragraph, heading, list-item, quote, button, details (summary + เนื้อ), table cell, image (alt, caption), cover/media-text (ข้อความข้างใน) · + `post_title`, `post_excerpt`
- ส่ง HTML fragment ให้ provider พร้อมคำสั่งให้คงแท็ก inline (`<strong> <em> <a> <br>`) และ attribute ไม่เปลี่ยน · ห้ามแปล URL (ลิงก์ภายในแปลงตอน render ด้วย `hri_localize_url()` อยู่แล้ว), shortcode, ตัวเลขราคา/วันที่, ข้อความภาษาอังกฤษล้วนที่อยู่ใน glossary แบบ "ไม่แปล"
- attribute ของ block ที่เป็นข้อความ (alt, caption, label ของ hri blocks) — ทำ allowlist ต่อชื่อ block
- **ID ของ segment**: ใส่ `metadata.hriId` (uuid สั้น) ให้ block ต้นฉบับตอนบันทึก ถ้ายังไม่มี และ copy ไปที่ block ในหน้าแปล → จับคู่ block ข้ามภาษาได้แม้มีการแทรก/ย้าย block
  - ⚠️ **ต้องพิสูจน์ก่อนทำต่อ**: editor ของ core เก็บ key ที่ไม่รู้จักใน `metadata` ไว้หลังเปิด-บันทึกไหม (ทั้งต้นฉบับและหน้าแปล) · ถ้าไม่เก็บ ใช้ fallback: จับคู่ตามลำดับ block + ชื่อ block + hash และยอมรับว่าการย้าย block จะทำให้แปลใหม่
- meta ของหน้าแปล `_hri_tr` (JSON): `{ hriId: { src: <hash ข้อความไทย>, mt: <hash คำแปลเครื่อง>, state: machine|human|outdated } }` + สถานะรวมของหน้า + เวลา/ยอดที่แปลล่าสุด
- คนบันทึกหน้าแปล (ไม่ใช่ระบบ) → block ที่ hash ปัจจุบัน ≠ `mt` = `human`
- ต้นฉบับเปลี่ยน → block ที่ `src` ไม่ตรง: ถ้า `machine` = แปลใหม่ทับได้ · ถ้า `human` = ไม่ทับ ตั้ง `outdated` + เก็บคำแปลเครื่องใหม่ไว้เป็นข้อเสนอ · block ใหม่ = แปลแล้วแทรกตามตำแหน่ง · block ที่ลบในต้นฉบับ = ลบในหน้าแปลถ้า `machine`, ถ้า `human` ขึ้น ⚠️

### 4.3 สิ่งที่แปลนอก post content
- คอร์ส: meta ที่ "copy ครั้งแรกแล้วแปลเอง" = ทุก meta ของคอร์ส **ยกเว้น** `hri_synced_course_meta()` (`polylang.php`) และตัวเลข/URL — ตรวจรายการจริงตอนทำ (เช่น `hri_audience`, `hri_location`, `hri_price_note`, `hri_schedule_text`, `hri_time_text`)
- วิทยากร (`trainer`): ชื่อ, เนื้อหา
- term คอร์สที่ `hri_name_en` / `hri_name_ja` ยังว่าง → เติมให้ (term ไม่มีสถานะ review แยก แสดงในหน้า "งานแปล" เป็นรายการแยก)
- slug: Polylang ฟรีห้าม slug ซ้ำข้ามภาษา → EN = slug จากชื่ออังกฤษที่แปลได้ (ถ้าซ้ำต่อ `-en`), JA = slug ของ EN ต่อ `-ja` · **ตั้งครั้งแรกครั้งเดียว** ห้ามเปลี่ยนเมื่อแปลใหม่ (URL ต้องนิ่ง)
- ช่อง SEO (title/description ของ The SEO Framework) — ทำต่อในงาน D ถ้ายังไม่ได้ติดตั้ง

### 4.4 อภิธานศัพท์และน้ำเสียง
- เก็บใน option แก้ได้ใน Settings → การแปล (ตาราง: ไทย | EN | JA | ไม่แปล) · ค่าเริ่มต้นจากของที่มี: ชื่อแบรนด์, ชื่อหลักสูตร, ชื่อวิทยากร, In-house, Public Training, DO·WA·KEI, ชื่อ term ที่มีคำแปลแล้ว
- คำสั่งน้ำเสียง (แก้ได้): EN = professional B2B, กระชับ · JA = 敬語 です/ます, B2B, ไม่แปลตรงตัว
- ส่งเฉพาะ glossary entries ที่เจอในข้อความนั้น (ประหยัด token)

### 4.5 คิว
- `save_post` ของต้นฉบับไทยที่ publish (ข้าม autosave/revision/บันทึกโดยระบบเอง) → ตั้ง event `hri_translate_post( $id, $lang )` หน่วง 60 วินาที (กดบันทึกถี่ = รวบเป็นครั้งเดียว)
- lock ต่อโพสต์ต่อภาษา (transient) · ส่ง segment เป็นชุด (batch ต่อ request ตามขนาด) · retry 3 ครั้งแบบ backoff · error เก็บใน meta + แสดงในหน้า "งานแปล"
- ปุ่ม "แปลใหม่ตอนนี้" ในกล่อง "การแปล" (เข้าคิวทันที) และ "แปลทั้งหน้าใหม่" (ล้างสถานะ — ยืนยันก่อน เพราะทับงานคน)
- หลังอัปเดตหน้าแปล: purge cache URL นั้น (Rcache — รอคำตอบข้อ 3.4)

### 4.6 การเผยแพร่และ SEO
- นโยบายต่อภาษา: `publish` | `publish_noindex` | `draft`
- `publish_noindex` + สถานะ ≠ `reviewed` → `wp_robots` ใส่ `noindex` · ตัดออกจาก sitemap · **hreflang ต้องไม่ชี้ไปหน้าที่ noindex** (เช็คร่วมกับงาน D)
- ไม่ต้องแสดงป้าย "แปลด้วย AI" บนหน้าเว็บ (ถาม Jimmi ถ้าลูกค้าอยากได้)

### 4.7 หน้า "งานแปล" (เมนูหลังบ้าน) และการแจ้งเตือน
- ตาราง: หน้า | ภาษา | สถานะ | ต้นฉบับแก้ล่าสุด | แปลล่าสุด · กรองตามภาษา/สถานะ · ลิงก์ไปแก้
- ยอดใช้งานเดือนนี้ (ตัวอักษร/token + ค่าใช้จ่ายโดยประมาณ) · ถึงงบ = หยุดเข้าคิว + แจ้งเตือนใน admin + อีเมล
- อีเมลสรุปวันละครั้งถึงคนตรวจของแต่ละภาษา (เฉพาะวันที่มีงาน)
- สิทธิ์: v1 ใช้ role Editor เดิม (Polylang ฟรีจำกัดสิทธิ์ต่อภาษาไม่ได้) · จดไว้ถ้าต้องการ role "ผู้ตรวจ JA" ทีหลัง

### 4.8 ความปลอดภัย / ข้อมูล
- ส่งเฉพาะเนื้อหาสาธารณะของโพสต์ ห้ามส่งข้อมูล Lead (`hri_lead`) หรือข้อมูลผู้ใช้
- ไม่ log ข้อความเต็มลง debug.log (log แค่ id/สถานะ/ขนาด)
- ทุก action ในหลังบ้านมี nonce + capability check

## 5. แบ่งเฟส (ทำในแชทเดียวได้ถ้าไม่ใหญ่เกิน ถ้าใหญ่ให้แบ่งตามนี้)

1. **เฟส 1**: settings + provider adapter + `fake` + segment + แปลครั้งแรก (สร้างหน้าแปล) ของ page/course/post/trainer + กล่อง "การแปล" + คอลัมน์สถานะ · พิสูจน์เรื่อง `metadata.hriId` ก่อน
2. **เฟส 2**: แปลใหม่เฉพาะ block ที่เปลี่ยน + ตรวจจับงานคน + `outdated` + ปุ่มตรวจแล้ว + noindex
3. **เฟส 3**: หน้า "งานแปล" + glossary UI + อีเมลสรุป + งบ/ยอดใช้ + term names

## 6. การทดสอบ (ขั้นต่ำ)

ใช้ provider `fake` ใน local (`scripts/local-setup.sh` + Polylang จาก GitHub)
- สร้างหน้าไทยใหม่ที่มีทุกชนิด block ที่รองรับ + ลิงก์ภายใน + ตัวหนา → หน้า EN/JA เกิด, block valid ใน editor (ไม่มี "This block contains unexpected content"), แท็ก inline ครบ, ลิงก์ไปหน้าภาษานั้น (ตอน render)
- แก้หน้า JA บาง block ด้วยมือ → แก้ไทย block อื่น → block ที่คนแก้ไม่เปลี่ยน, block อื่นแปลใหม่
- แก้ไทยใน block ที่คนแก้ไว้ → ⚠️ `outdated`, ไม่ทับ
- แทรก/ย้าย/ลบ block ในต้นฉบับ → หน้าแปลตามได้ถูกตำแหน่ง
- คอร์ส: meta ที่ sync ยัง sync, meta ที่แปลถูกแปล, slug ตั้งครั้งเดียว
- บันทึกถี่ 5 ครั้งใน 1 นาที → แปลครั้งเดียว · provider error → retry แล้วขึ้น ❌ พร้อมปุ่มลองใหม่ · ไม่มี key → โมดูลปิด ไม่มี PHP notice
- `noindex` เฉพาะหน้าที่ยังไม่ตรวจของภาษาที่ตั้ง `publish_noindex`
- `python3 -I scripts/measure.py` ผ่านเหมือนเดิม
- ถ้ามี key จริง (Jimmi ให้มาเฉพาะตอนทดสอบ ใส่ใน wp-config ของ local เท่านั้น): แปลจริง 1 คอร์ส + 1 บทความ แล้วบันทึกยอด token/ค่าใช้จ่ายจริงลงข้อ 7

## 7. ค่าใช้จ่าย (เติมหลังทดสอบจริง)

## 8. สรุปสำหรับลูกค้า (ใช้ประกอบใบเสนอราคาได้)

ทีมการตลาดเขียนภาษาไทยที่เดียว ระบบสร้างหน้าอังกฤษและญี่ปุ่นให้อัตโนมัติภายในไม่กี่นาที ใช้คำศัพท์เฉพาะ (ชื่อหลักสูตร ชื่อวิทยากร) ตรงกันทุกหน้า ถ้ามีผู้ตรวจภาษา เข้าไปแก้ได้ในหน้าเดียวกับที่ใช้อยู่ และสิ่งที่แก้จะไม่ถูกเขียนทับเมื่อภาษาไทยเปลี่ยน หน้าภาษาญี่ปุ่นที่ยังไม่ผ่านการตรวจจะไม่ถูก Google เก็บ จนกว่าจะตรวจ ค่าใช้จ่ายจ่ายตามจริงต่อการแปล ตั้งเพดานรายเดือนได้ ไม่มีค่า license รายปี
